OSF Autonomous NPC Interactions — Changelog
=============================================

v1.0.4 — 2026-09-10 — Spaceflight Critical Hotfix
-------------------------------------------------------------------------
BUGFIX: Fixed an issue where NPCs would spawn and get stuck in animations outside the ship during spaceflight.
  Root cause: The mod previously checked if the player was sitting in *any* furniture to block scenes (`GetSitState() != 0`). 
  This logic failed during 3rd-person flight or fast-travel to space, allowing scenes to start while the ship was moving. 
  Since OSF scenes pin actors to static world coordinates, they would clip outside the moving ship. Worse, if left behind in a space cell, they would permanently lose navmesh when the cell unloaded, causing severe engine lag.
  
  Fix: Replaced the sit-state check with a strict check for active piloting (`GetSpaceship() != None`).
  Additionally, added a new check to instantly clear all active scenes when the player takes the pilot seat (`OnSit` event) and unconditionally purge ghost scenes when landing in an exterior space cell (`OnLocationChange`). 
  Scenes can still properly trigger if you stand up from the pilot's seat and walk around the ship interior in orbit.

AFFECTED FILES:
  Data/Scripts/Source/OSF_AutonomousManagerScript.psc
  Data/OSFAutonomous.esm
  fomod/info.xml
  README.txt

v1.0.3 — 2026-09-08 — Header cleanup (removed legacy TES4.DATA subrecord)
-------------------------------------------------------------------------
BUGFIX: Removed legacy DATA subrecord from TES4 header in OSFAutonomous.esm.
  Root cause: Previous release builds included an 8-byte DATA subrecord
  after the MAST entry, a carryover from Skyrim/Fallout 4 plugin conventions.
  Starfield's Creation Engine 2 does not use this subrecord, and mod tools
  (such as Wrye Bash) rejected the plugin with:
  "Unexpected subrecord: TES4.DATA".

  Fix: Rebuilt plugin header with only canonical Starfield subrecords
  (HEDR, CNAM, MAST, BNAM, INCC). File size reduced from 316 B to 311 B.
  Clean and error-free in all mod managers and diagnostic tools.

AFFECTED FILES:
  Data/OSFAutonomous.esm  — updated ESM without legacy DATA subrecord
  fomod/info.xml          — version bumped to 1.0.3
  README.txt              — version bumped to 1.0.3

v1.0.1 — 2026-09-03 — FOMOD fix for MO2 + Vortex compatibility
------------------------------------------------------
BUGFIX: FOMOD installer blocked installation in Mod Organizer 2.
  Root cause: <fileDependency> entries in ModuleConfig.xml checked for
  physical presence of "SFSE\Plugins\OSF Animation.dll" and "OSFUI.dll".
  MO2 uses a virtual file system (VFS) — mod files are not physically
  in Data\, so the FOMOD dependency check failed even when the DLLs
  were correctly installed through MO2.

  Fix: Removed all <fileDependency> entries from <moduleDependencies>.
  The "Requirements Check" install step is now always visible and
  informational only — the user acknowledges dependencies manually.
  Runtime dependency validation via OSF.IsReady() in the Papyrus script
  is unaffected and still catches missing OSF at game load.

BUGFIX: Vortex reported Invalid XML (Sch_UndeclaredAttribute +
  Sch_MissRequiredAttribute). Root cause: attributes not declared in
  the ModConfig5.0.xsd schema:
    - "name" on <gameDependency> — undeclared (versionDependency type
      only declares "version" as required)
    - "display" on <fileDependency> — undeclared (only "file" and
      "state" are declared)
  Fix: Removed the entire <moduleDependencies> block. <gameDependency>
  cannot be made schema-compliant without introducing a version string
  that Vortex would also validate. The dependency check was redundant
  with the informational "Requirements Check" install step.

  Note: The first v1.0.1 build uploaded to Nexus still contained
  <gameDependency name="Starfield" />. It was replaced with a fully
  schema-compliant build (no <moduleDependencies> at all).

v1.0.0 — Initial Release

- Tier-based scene selection (T1-T5) with pack-specific and fallback tiers
- FF support via MF fallback animations

- Romance exclusivity guard, walk-in interrupt, inter-scene proximity guard
- 4 custom female voice clips (mono WEM)
- FOMOD installer with Vortex support
- Requires: SFSE, OSF Animation, OSFUI
